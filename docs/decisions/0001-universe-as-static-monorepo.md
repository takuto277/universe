# 0001 universe を静的モノレポとして維持する

- Status: Amended by [0010](0010-monorepo-role.md)
- Date: 2026-10-19

## Context

universe は個人の学習と発表を兼ねたアプリ置き場です。アプリごとに目的や技術は変わりますが、どれも小規模で、GitHub Pages でそのまま配信できます。リポジトリをアプリごとに分けると、公開設定・共通テスト・一覧更新のコストが先に増えます。

> 現在の配置は [0010](0010-monorepo-role.md) を参照してください。アプリは `projects/` 配下に置きます。

## Decision

- 1つのリポジトリに複数アプリを置く
- アプリはトップレベルのディレクトリとし、ビルドなしの静的ファイルで動かす
- 公開アプリの一覧は `apps.json` を正とする
- 共通のテスト基盤は `tools/` に置き、`jsc` で実行する
- 一覧・リンク・README・テストの整合性を `tools/check_site.py` で検査する

## Consequences

良い面:

- 共通のテストと公開設定を一度だけ管理できる
- アプリ間でハーネスや書き方を再利用できる
- 学習の記録と実装を同じ履歴に残せる
- ビルドやサーバーが不要で、公開が単純

制約:

- 依存関係をアプリごとに分離しにくい
- リポジトリ全体の CI 時間が増える
- 公開範囲をアプリごとに変えられない

## Alternatives

- アプリごとにリポジトリを分ける: 再利用部品が増え、公開設定が重複するため、今の規模では見送る
- Vite などのビルド基盤を入れる: 型や依存管理は便利だが、最初の学習対象を増やすため見送る
- サーバーアプリを同居させる: GitHub Pages では動かないため、必要になった時点で別リポジトリを検討する

## 分割の条件

次のいずれかが実際に困り始めたら、アプリまたは共通ツールの切り出しを検討します。

- 別リポジトリから共通ツールを再利用したくなった
- 公開範囲やデプロイ頻度がアプリごとに分かれた
- 依存関係や CI 時間が無視できなくなった
