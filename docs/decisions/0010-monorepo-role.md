# 0010 universe を「無人開発基盤のモノレポ」と定義する

- Status: Accepted
- Date: 2026-10-28

## Context

universe は静的ゲームの公開場所として始まり、その後に Issue から PR までを無人で回す開発基盤を同じリポジトリへ追加しました。その結果、次の2つの役割が同じ階層に混在し、README・Issue・PR のどれが主目的か分かりにくくなりました。

- ブラウザゲームの作品集
- ゲームを実装・レビュー・公開する無人開発基盤

ゲームを完全に切り離すと、基盤の検証材料と公開物がなくなり、自己改善ループの実例も失われます。一方で、ゲームを主役にすると、基盤の改善が「ゲーム開発の手段」に見えてしまいます。

## Decision

universe の役割を次の一文で定義します。

> universe は、ゲームを題材に無人開発基盤を育てるモノレポ。

配置と責務は次の通りです。

- `tools/`: 本体（platform）。Issue → 実装 → PR → レビュー → マージを担う
- `projects/`: 題材と公開物。ゲームを目的別に配置する
  - `projects/<name>/`: 公開・継続保守の対象
  - `projects/_labs/<name>/`: 実験・検証・試作
  - `projects/_samples/<name>/`: 教材・テンプレート・最小実装
- `docs/`: 横断知識。運用手順、ADR、学習ログを置く

移行はビッグバンではなく段階的に行います。

- 旧URLはリダイレクトで維持する
- 進行中ブランチがあるゲームは、その収束を待ってから移動する
- `tools/` は LaunchAgent と専用チェックアウトの互換性を確認してから `projects/universe-agent/` へ移す

## Consequences

良い面:

- 「何のためのリポジトリか」を一文で説明できる
- ゲームと基盤の変更を、同じバックログで管理しつつ責務を分けられる
- ゲームは公開物であると同時に、基盤の検証材料として再利用できる
- 移行中でも旧URLと既存の自動化を壊さない

トレードオフ:

- 移行完了まではルート直下にゲームと `tools/` が残る
- `projects/` の分類判断が必要になる
- `tools/` の移行では一時的な互換ラッパーを維持する必要がある
