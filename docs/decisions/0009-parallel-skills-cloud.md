# 0009 並列ワーカー・スキル配布・クラウド実行の段階導入

- Status: Accepted
- Date: 2026-10-23

## Context

ADR 0005/0006/0008 で、1件ずつの無人実装・自動修正・改善ループは動くようになった。Issue #21 では、u7chan の基盤と比較して不足している「並列ワーカー」「スキル配布」「クラウド実行」「モデルの役割別ルーティング」を検討する。すべてを一度に入れると、排他制御と検証が複雑になる。

## Decision

- **スキル配布（今回実装）**: `.opencode/skills/` を `registry.json` でバージョン管理し、`tools/check_skills.py` で契約検査する。`unattended-ops` を追加し、配布方法を [docs/skills.md](../skills.md) に書く
- **モデルの役割別ルーティング（今回実装）**: builder/fix は `UNIVERSE_AGENT_MODEL`、planner は `UNIVERSE_AGENT_PLANNER_MODEL`、レビューは `UNIVERSE_AUTO_PR_MODEL` を使う
- **並列ワーカー（保留）**: 2スロット化は、Issue の選択〜claim をロックし、スロット別ロックと Issue 別 worktree を使う設計で段階導入する。前提として専用チェックアウト（PR #81）が安定している必要がある
- **クラウド実行（保留）**: GitHub Actions で AI を動かす案と、リモートサンドボックス案を比較する。API キーの管理とコストが見合うまでローカルを維持する

## Consequences

良い面:

- スキルの契約が機械的に検証され、配布・版管理の土台ができる
- planner だけ別モデルにして、コストや得意分野を分けられる
- 並列化とクラウド化は、排他制御・認証・コストの設計を先に固めてから進められる

制約:

- スキルはリポジトリのツールに依存し、そのまま他リポジトリでは動かない
- 並列化は未実装。現状は1件ずつ
- クラウド化は未実装。Mac のログイン中のみ動く
- モデルを分けると、応答の一貫性やテストの再現性は別途確認が必要

## Alternatives

- すべて同時に実装する: 排他制御と検証が複雑になり、障害時の切り分けが難しい
- スキルを外部パッケージにする: 配布は楽だが、このリポジトリの運用との同期が難しくなる
- 最初からクラウドで動かす: API キーとコストの管理が必要で、個人開発の範囲を超える
