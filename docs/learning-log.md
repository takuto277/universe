# 学習ログ

アプリを作りながら学んだことを、後から読み返せる形で残します。完璧な文章より、次に同じ問題に当たったときに思い出せることを優先します。

## 書き方

```markdown
## YYYY-MM-DD アプリ名

- やったこと:
- 学んだこと:
- 詰まったこと:
- 次に試すこと:
```

## 2026-10-20 janken-game

- やったこと: 心理戦じゃんけん「手を読め!」を追加した。生 WebGL のミニ 3D で手を描き、連勝ボーナス・見切りゲージ・先読み必殺と、プレイヤーの出しグセ(直前の手→次の手)を学習する CPU を組み合わせた。
- 学んだこと: レンダラを独立させ、WebGL が使えない環境では `create()` が null を返して描画だけスキップする設計にすると、スモークテストのスタブ環境でもゲーム進行をそのまま検証できる。読みの学習を遷移表の確率として持つと、固定乱数と組み合わせて挙動を数値で検証しやすい。
- 詰まったこと: テストで読み判定の乱数消費数を読み違えて失敗した(遷移データがないラウンドは読み判定の乱数を消費しない)。乱数消費は分岐の短絡まで含めてテストを書く必要がある。
- 次に試すこと: CPU クセの追加、演出(カメラワーク・パーティクル)の強化、対戦履歴の保存。

## 2026-10-19 baseball-game

- やったこと: 守備中の自分の投球傾向と、CPU に読まれている度合いを表示した。タイミングバーに単打・二塁打・ホームランの目安を追加した。
- 学んだこと: 読み精度の計算を `readAccuracy` として副作用なしで切り出すと、CPU の判断と表示で同じ値を使え、テストもしやすい。UI の表示は、ゲームの状態から毎回組み立てる方が状態の二重管理を避けられる。
- 詰まったこと: 投球履歴の更新と読み精度の計算が同じ関数に混ざっていた。計算だけを先に切り出すことで、表示用の値と実際の判断がずれないようにした。
- 次に試すこと: スマートフォンでの操作確認、キーボード操作の抜け漏れ確認、試合結果の保存。
