# WORD FRONT しりとり陣取り

8×8 のひらがな盤面をなぞって、しりとりで陣地を奪い合うブラウザゲームです。あなた（朱）と CPU（藍）が交互に 2〜6 文字の単語を作り、通過したマスを陣地にしていきます。3 分後に陣地が多い方が勝ちです。

外部通信・外部フォント・外部音源は使いません。`index.html` を開くだけで遊べます。

## 遊び方

- 最初の単語は、光っている好きなマスから始められます。
- 2 語目以降は、**前の単語の最後のマス（カーソル）**が開始マスになります。開始マスは前の単語の最後の文字なので、しりとりの「次の文字」が自然に満たされます。
- マスは 8 方向（上下左右と斜め）にだけつながります。
- 同じ単語の中で同じマスを 2 回使うことはできません。
- 辞書にある 2〜6 文字の単語だけを確定できます。途中で「辞書に存在する接頭辞」でなくなる経路は選べません。
- 確定すると、**開始マスより後ろ**のマスが自分の陣地になります。相手の陣地を通過した場合は奪えます。開始マス自体は陣地になりません（前の単語の終点として共有されるため）。
- 最後のマスが次のカーソルになります。
- どちらかが単語を作れなくなったら、その時点で相手の勝ちです。
- 残り時間が 0 になったら、陣地の多い方が勝ちです。同数なら引き分けです。

## 操作

| 操作 | 内容 |
| --- | --- |
| マスをタップ | 経路の開始・延長 |
| 経路内の前のマスをタップ | そのマスまで戻す |
| もどす | 直前の 1 マスを取り消す |
| けってい | 現在の経路を単語として確定する |
| ヒント | 有効な経路を表示する。残り時間を 5 秒消費 |
| 音 ON/OFF | WebAudio の効果音を切り替える |
| キーボード | `Enter`/`Space` 確定、`U`/`Backspace` もどす、`H` ヒント、`M` 音、`R` やり直し |

ヒントは経路を現在の選択としてセットします。そのまま「けってい」できますが、続けて延長・ undo も可能です。

## スコア

- プレイヤーの陣地数 = `ownership` が 1 のマスの数。
- CPU の陣地数 = `ownership` が 2 のマスの数。
- 時間切れ時の勝敗は陣地数で決まります。陣地数が同じなら引き分け。
- 単語の長さや奪ったマス数はスコアではありませんが、1 手で得られる陣地が増えます。

## 辞書と盤面生成

### 辞書

`dictionary.js` に約 1,000 語（2〜6 かな）の内蔵辞書があります。重複を除去し、末尾が「ん」の単語は次の語につながらないため除外しています。次の API を持ちます。

```js
WordFrontDictionary.words      // 単語配列
WordFrontDictionary.size       // 語数
WordFrontDictionary.has(word)  // 完全一致
WordFrontDictionary.isPrefix(p) // 接頭辞判定
WordFrontDictionary.getTrie()  // 遅延構築した trie
```

ブラウザでは `window.WordFrontDictionary`、jsc では `load('dictionary.js')` 後のグローバル `WordFrontDictionary` として使えます。

### 盤面生成

`engine.js` の `generateBoard(seed)` は次の手順で決定的に盤面を作ります。

1. シードから線形合同法の乱数を作る。
2. 辞書から単語を選び、空きマスだけを使って 8 方向のランダム経路に配置する（1 枚に 12 語を目標）。
3. 残りの空きマスを、母音とよく使う子音を多めにした重み付きかなで埋める。
4. 8 語以上配置できなければ別の派生シードで再試行する。複数候補のうち、開始できるマスが最も多い盤面を採用する。最後の保険として蛇行経路に 9 語を強制配置する。

配置済みの単語は上書きしないため、生成後もその経路は必ず盤面上に残ります。同じ `seed` なら盤面・開始候補・初期状態は完全に同じになります。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | HUD、盤面 canvas、開始・終了オーバーレイ、ボタン |
| `style.css` | 和紙・墨・朱・藍のレスポンシブ UI。外部フォントなし |
| `dictionary.js` | 内蔵ひらがな辞書と trie / `has` / `isPrefix` |

| `test-engine.js` | 辞書・経路・陣地・CPU・時間切れ・決定性のテスト |
| `test-smoke.js` | ハーネスで 1 対戦を自動実行するスモークテスト |

## 設計メモ

- `engine.js` は DOM に依存しません。`createGame({ seed, board, ownership, timeLimit, cpuDelay })` でゲームを作り、`state` と各メソッドを持たせています。テストでは `board` に任意の 64 マス配列を渡せるため、隣接・再利用・奪取・手詰まりを小さな盤面で検証できます。
- 盤面は 64 要素のフラット配列です。`index = y * 8 + x`。`E.indexOf(x, y)` / `E.xOf(index)` / `E.yOf(index)` も公開しています。
- 辞書は trie にして、経路延長時の接頭辞判定と CPU / ヒントの DFS に使います。
- CPU はカーソルから DFS し、`(文字数 - 1) * 100 + 奪える相手陣地 * 70` で候補を選びます。長い単語と奪取を優先し、同点は探索順で決まります。CPU の着手は `update(dt)` 内の短い思考時間後に実行されます。
- `game.js` の rAF ループが `engine.update(dt)` を呼び、タイマーと CPU の思考を進めます。`__GAME__.autoPlayStep()` はプレイヤーの手番だけを AI で進め、`update` は呼びません（ハーネス側が仮想時間を進めるため）。
- 和紙はオフスクリーン canvas に一度だけ描画し、毎フレームは `drawImage` します。盤面の朱・藍の陣地、ブラシ風の経路、カーソルの脈動、開始候補の点滅を canvas で描きます。
- `localStorage` と `AudioContext` は存在しない場合も含めて try/catch で扱います。

## テスト

```sh
cd projects/_labs/word-front
jsc test-engine.js
jsc test-smoke.js
```

`jsc` が PATH にない場合:

```sh
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc test-engine.js
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc test-smoke.js
```

`test-engine.js` は次を検証します。

- 辞書の語数・文字種・重複・`has` / `isPrefix`
- 同じ seed の盤面決定性と配置語数
- 8 方向の隣接、同一単語内の再利用禁止、接頭辞でない延長の拒否
- 開始マスを陣地にしないこと、通過した相手陣地の奪取、カーソルの前進
- 手番交代と CPU の着手
- カーソル以外から始められないこと
- 手がない側の負け
- 時間切れ時の陣地比較
- ヒントの 5 秒コスト
- 自動プレイが有限時間で終了すること

`test-smoke.js` は `tools/harness.js` で DOM / Canvas / rAF をスタブし、`game.js` を含めた 1 対戦を最後まで自動実行します。終了状態、スコア、エンド画面、スタート画面の非表示、`console.error` の有無を確認します。

## 既知の制限

- 辞書は一般的なひらがな表記のみです。カタカナ語、漢字、長音「ー」、人名・固有名詞はほぼ含みません。
- 同じ単語を何度使ってもよいルールです（しりとりの「一度使った語は禁止」は実装していません）。
- CPU は 1 手先だけを見る貪欲法です。数手先の詰みや、相手に手を残すかどうかの読みはしません。
- 盤面生成は「配置した単語が残る」ことを保証しますが、すべてのカーソル位置から必ず語が作れることは保証しません。手詰まりはルールどおり即座に勝敗になります。
- 画面はタップ操作を主対象にしています。キーボード操作は補助的です。
- 効果音はブラウザの自動再生制限により、最初のユーザー操作まで鳴らないことがあります。
