# 手を読め!

心理戦じゃんけんゲームです。じゃんけんの勝ち負けだけでなく、連勝ボーナス・見切りゲージ・必殺「先読み」、そして CPU による出しグセの学習を組み合わせています。手は生 WebGL のミニ 3D でテーブル上に描きます。依存ゼロの静的ファイルで動きます。

## 遊ぶ

universe のルートで次を実行し、http://localhost:8000/projects/_samples/janken-game/ を開きます。

```sh
python3 -m http.server 8000
```

## ルール

- お互い HP 8。じゃんけんで勝つと 1 ダメージ、相手の HP が 0 になったら勝ち
- 3連勝目からは連勝ボーナスで 2 ダメージ
- あいこはノーカウント(ダメージなし、連勝は途切れない)
- 勝つと見切りゲージが 1 つ溜まる(最大 3)。満タンで必殺「先読み」が使え、CPU の手を見てから選べる。先読み中の勝ちは 3 ダメージ
- CPU には試合ごとのクセ(style)がある: 「ぐうたろう」はグー多め、「まねっこ」はあなたの前の手をまね、「あとだし」は勝つ手を出し、「ぐるぐる」はグー→パー→チョキと循環
- さらに CPU はあなたの「直前の手 → 次の手」の遷移を学習する。出す手が偏るほど「CPUの読み」が上がり、カウンターを合わせられやすい

### キー操作

| キー | 動作 |
| --- | --- |
| `1` | グー |
| `2` | チョキ |
| `3` | パー |
| `4` | 先読み(見切りゲージ満タン時) |
| `Space` | 開始・再戦 |

画面下のボタンでも同じ操作ができます。

## 構成

| ファイル | 役割 |
| --- | --- |
| `engine.js` | 勝敗・ダメージ・ゲージ・CPU の意思決定と読みの学習。描画に依存しない |
| `renderer.js` | 生 WebGL のミニ 3D レンダラ。手(グー/チョキ/パー)をテーブル上に描く |
| `game.js` | 画面描画、入力、進行(先読み、リビール演出、結果表示) |
| `index.html` | 画面の骨格とルール説明 |
| `style.css` | レイアウトと見た目 |
| `test-engine.js` | エンジンの仕様テストとバランスシミュレーション |
| `test-smoke.js` | 1試合を自動プレイするスモークテスト |

## テスト

universe のルートで実行します。

```sh
./tools/run-tests.sh
```

個別に実行する場合:

```sh
cd projects/_samples/janken-game
jsc test-engine.js
jsc test-smoke.js
```

`jsc` が PATH にない場合は、macOS 標準の `/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc` を使うか、`JSC` 環境変数で指定してください。

## 設計メモ

- ゲームの判断と状態は `engine.js` に寄せ、`game.js` は表示と入力に徹する
- 乱数は引数で差し替えられるようにし、テストでは固定する(読みの学習も遷移表の数値で検証する)
- 適応読みは「平滑化した最大遷移確率」から読み精度を計算し、上限を設けて理不尽にならないようにする
- バランスは大量シミュレーションの結果を見て調整する。特定の1試合の結果だけに合わせない
- `renderer.js` は WebGL が使えない環境では `create()` が `null` を返し、呼び出し側は描画をスキップして進行だけ続ける(スモークテストのスタブでも同じ経路を通る)
- 3D の座標系・カメラは `renderer.js` 内で完結させ、ゲーム側は「どの手を・どんな演出で」だけを渡す
- Canvas のサイズは `ResizeObserver` でステージに追従させる

## 既知の制限

- WebGL が使えない環境では 3D 表示が出ない(ゲーム進行と HUD は動く)
- 保存機能はないため、リロードすると試合は消える
- 画面サイズによっては一部の情報が折り返される
